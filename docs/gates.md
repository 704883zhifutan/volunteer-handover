# 试点门禁（G1 / G2 / G3）

这三个门禁不关，工具只做桌面推演。`scripts/deploy.sh` 会读本文件：只要有任意一个 `- [ ]`，
就拒绝出包。

**关闭方式**：把对应行改成 `- [x]`，并在"签字"一栏写明是谁、哪天、依据什么确认。
只改勾不改签字，视为未关闭——门禁关的是"标准已定"，不是"看起来准备好了"。

---

## G1 判定方法：怎么算"发现了全部重叠"

- 先说清"重叠"的判定口径：同一人员代号、时间窗相交、岗位不同。首尾相接（A 到 12:00、
  B 从 12:00 起）算不算重叠，必须由业务方拍板。
- 再说清怎么抽样：回放 50 次调班，是全量比对还是分层抽样；金标由谁标注（两个人各标一遍、
  分歧怎么裁）。
- 最后说清"漏一条"和"多报一条"各自的后果，用来定 G1 的通过标准。

- [ ] 判定口径已书面确认
- [ ] 金标标注人与分歧裁定人已指定
- [ ] 抽样方式与通过标准已确认

责任人：傅景（审核与质量）+ 秦芮（数字化）
需补证据：一份书面口径说明、一份 50 次调班的抽样清单

## G2 队列与叫停：谁值守、多久响应、谁能停

- 人工队列谁值守：工作时间内谁看、换班怎么交接、无人值守时清单是否照常出。
- 响应时限：一条未复核缺项最多压多久。这一条直接决定"清单会不会变成没人看的报表"。
- 谁有权暂停试点：出现假状态、越界指派、确认人被绕过时，谁能立刻叫停、怎么通知现场。

## G3 "完成"的定义

- 班次"完成"是指志愿者到岗、还是指交接确认完成？两者差一整个夜班。
- 客户侧（叶书）看到的口径必须与内部一致，否则会出现"我们显示已完成、客户说没人交接"。
- 这一条没定，代码里就不写 `is_complete`——宁可输出信号，也不输出一个会误导人的布尔值。

- [ ] 内部"完成"定义已确认
- [ ] 客户侧口径已由叶书确认一致
- [ ] 未交接但已到岗的情形如何处理已确认

## 附：与验收指标的关系

门禁不等于验收。关闭三门禁只说明"标准定了"，能不能扩范围还要看 W3 金标比对的结果：
召回率、误报率、核对工时、返工次数先测基线再谈阈值；确认完整率与必要复核保留率是硬门，
必须 100%，不参与权衡。
