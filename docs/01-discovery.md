# 01 · 业务挖掘：赛事志愿者排班与交接

> **文档来源**：实验室系统生成的访谈汇总（36/36 角色覆盖，事实编号 f00–f55），经人工整理。
> **性质**：待验证的需求假设，不是验收结论。
> **虚构声明**：企业名称与公开业务方向有公开来源；人物、指标与业务问题为演练虚构，不代表集团或成员企业实际。

## 1. 这次挖掘要回答什么

一句话诉求（顾明岚）：

> 围绕志愿者班次，**减少重复核对**，**提高服务可追溯性**；必须保留人工确认与可追溯来源。

因此挖掘不是问"你想不想要个系统"，而是回答四个可证伪的问题：

| 问题 | 判定标准 | 当前状态 |
|---|---|---|
| 重复核对具体发生在哪一步？ | 能指出步骤、频次、参与人 | ⚠️ 部分（缺工时基线） |
| 现有工具为什么不解决问题？ | 能指出缺哪张表、缺哪个字段 | ✅ 已定位（三套工具、无统一编号） |
| 什么绝对不能自动化？ | 能指出越界的后果与叫停人 | ✅ 已明确（医疗/安保、对外承诺、"完成"判定） |
| 怎么算做完？ | 有分母、有判定人、有金标 | ⚠️ 口径未闭合（G1/G3） |

## 2. 方法：六个人，各说一段

访谈覆盖 6 类角色、36 个访谈单元，逐条落成带编号的事实（f00–f55）。每个人只了解自己那段，**单一角色的说法一律不算事实**，必须两个角色以上交叉。

| 角色 | 他关心的 | 他给的约束 | 事实区间 |
|---|---|---|---|
| **顾明岚** · 业务负责人 | 范围与决策 | 只开一个批次试点；不自动指派医疗/安保；不替代现场指挥 | f00–f05 |
| **林亦舟** · 赛事现场协调员 | 现场能不能用 | 要一页缺项清单 + 来源位置，不要长摘要；建议不能覆盖原值 | f10–f15 |
| **唐映秋** · 项目流程协调员 | 流程闭环 | 交接须列最新版本、未结项、截止时间；版本靠有效期+确认状态，不靠文件名 | f20–f25 |
| **秦芮** · 数字化工程师 | 数据可得性 | 三套工具各自导出；只读脱敏；缺失值 ≠ 未确认值；读不到留快照 | f30–f35 |
| **傅景** · 审核与质量负责人 | 能不能背书 | 无法确认就进人工队列、可暂停试点；练习结果不得当业务指令 | f40–f45 |
| **叶书** · 客户协同代表 | 对外口径 | 系统不自动对外承诺；投诉先登记原始问题与版本 | f50–f55 |

## 3. 现状链路

```
岗位需求 → 人员匹配 → 班次确认 → 签到 → 现场交接
   ↑            ↑          ↑         ↑         ↑
 经验排       群消息      文件名     纸质/群    口头交接
```

关键事实：

- **f01**：真实链路是这五段，先观察每个交接点，而不是直接上自动化。
- **f10**：现场靠群消息；**排班表不反映缺岗**。
- **f11**：出现过替补被重复安排到两个点位（模拟异常，正是 C2 要抓的）。
- **f13**：先群消息、后补表；**回填时间经常被当成发生时间**。
- **f30**：三套工具（内部服务台 / 业务台账 / 文件库），**没有统一关联编号**。
- **f20**：交接记录必须写接收人、版本、未结项；**f23** 未结项要带截止时间。

## 5. 从事实到需求假设

六条需求，**不是六个功能**：REQ-1 与 REQ-2 是唯一产物，REQ-3 / REQ-4 是数据前提，REQ-6 零技术成本必须先落，REQ-5 是验收方法。

| 编号 | 假设 | 依据 | 可证伪判定 | 优先级 |
|---|---|---|---|---|
| **REQ-1** | 以"版本有效期 + 确认状态"为核心的交接责任清单，能减少重复核对 | f20 f23 f24 f25 | 回放 50 次调班，清单能覆盖每次调班的全部未结项且无重复条目 | P0 |
| **REQ-2** | 一页缺项清单 + 来源位置，优于泛化摘要，且必须保留人工复核 | f10 f11 f14 f15 | 当班人能在 60 秒内定位到原始行；建议不被误当成结论 | P0 |
| **REQ-3** | 业务发生时间与系统接收时间分离，是识别过期与回填的前提 | f13 f34 f35 | 用虚构记录可区分"回填"与"真实发生"；不预设延迟阈值 | P1 |
| **REQ-4** | 统一关联编号 + 关键字段对齐，是只读集成的前置条件 | f30 f31 f32 f33 | 重复编号/断链/单位差异能被定位且保留原行 | P1 |
| **REQ-5** | 验收须同时看工时、返工、确认完整率 | f51 f53 f55 | 三个数都能从原始记录复算；分母写清楚 | P1 |
| **REQ-6** | 无法确认版本或关键字段时进人工队列并可暂停 | f41 f44 f40 f45 | 队列有值守人、响应时限、恢复批准人 | P0 |

每条假设的判定方法都已写进 [05 设计方案](05-solution.md) §6 与 `docs/gates.md`。

## 6. 证据缺口（不许当承诺用）

| 编号 | 未核实的事 | 影响 |
|---|---|---|
| **H1** | 数据更新频率与可接受延迟阈值 | 无法判断"多旧算过期" |
| **H2** | 交接记录留存多久；虚构个人字段何时删除 | 合规边界 |
| **H3** | 版本变更/确认人变更/覆盖原始记录分别由谁审批 | 权限设计 |
| **H4** | 人工队列谁值守、响应时限、谁批准恢复 | 停止条件无法执行 |
| **H5** | 统一编号由谁生成、规则由谁定 | REQ-4 无法落地 |
| **H6** | 投诉与试点反馈的收集入口、责任人、时限 | 客户侧闭环 |

**采集 100% ≠ 需求已验证。** 覆盖率只说明材料收齐了，六条假设仍然全部处于"待验证"状态。

## 7. 结论：能做什么，不能做什么

**可以进试点的**（单批次、只读、一页纸）：

- 交接责任清单（含版本状态、未结项、归属）
- 一页缺项清单（缺岗、占位冲突、点位/人员不一致、版本过期、编号断链）
- 复核回填与三个指标（误报率、确认完整率、复核滞后）
- 批次对比（今天 vs 昨天）

**明确不做的**（写进报价与合同）：

- 写回任何系统、发外部消息、自动指派（尤其医疗/安保）
- 判定"交接是否完成"（G3 未定义）
- 替人下复核结论、替客户对外承诺
- 任何"零漏报"承诺——只承诺召回率可被金标证伪
